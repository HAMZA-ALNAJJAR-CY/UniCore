# UniCore architecture

## Implemented

Phase 0 is a client-rendered React/TypeScript SPA. `src/main.tsx` mounts the router and imports global styles. `src/app/App.tsx` defines routes and the persistent responsive shell. `src/app/navigation.ts` is the shared desktop/mobile navigation source.

`src/pages/` holds a dashboard, a data-driven placeholder page for each planned academic area, and a 404 page. `src/components/` contains PageHeader, EmptyState, and ToastProvider. `src/test/` contains shell integration tests, database tests, and DOM test setup. `src/styles.css` owns Tailwind 4 theme tokens and shell/component styles. The layout switches at 768px; cards adapt at 1100px and 360px. No network service layer exists.

Phase 1A adds `src/data/models.ts` (domain records), `database.ts` (internal versioned Dexie schema), `identity.ts` (canonical UUID handling), `validation.ts` (runtime validation), `errors.ts` (typed storage failures), `store.ts` (transactional repositories), and `index.ts` (public factory/types). UI consumers use the public factory, never direct tables. Importing or constructing the service neither opens nor seeds a database. Phase 1B opens it only when the timetable page requests review/read operations or explicitly saves.

All stores participate in write transactions to protect relationships across connections. Stable IDs and revision checks prevent stale replacement. Default reads hide tombstones. Cascade deletion requires a confirmed graph of dependency IDs/revisions. Actual file content lives in separate lecture/material Blob stores. No generic ORM or network adapters are introduced.

The hardening update adds `createRelated(RelatedBatch)` as explicit service-level atomic insert-if-absent orchestration. It processes terms, courses, sessions, lectures, materials, lecture files, then material files in parent-first order. It validates incoming candidates even when their identities exist; existing values are never replaced. Every candidate receives inserted/skipped/rejected status. A rejection rolls back all new writes; skipped existing records remain untouched. This is a storage API, not an import workflow. UUID casing is normalized only for known ID/reference fields. Version 2 preflights legacy UUID/term-code collisions before atomic rekeying and preserves all record content and metadata. Parent-filtered attachment lists use their parent indexes. Explicit lecture detachment preserves history before a session is deleted.

The six supplied colors are exposed as Tailwind tokens. Derived colors improve active state, border, and small-text readability. System fonts avoid a runtime font dependency. Motion is intentionally omitted. Semantic navigation, active link states, visible keyboard focus, safe-area padding, a skip link, and focus movement after route changes support accessibility. Toast announcements use a polite live region and a dismiss button; timers are cleaned up on unmount. Components must call `useToast()` within ToastProvider.

React Router handles navigation. date-fns formats the local dashboard date; it does not drive a countdown. Vite uses the React and official Tailwind plugins. TypeScript is strict; ESLint checks React hooks; Vitest uses jsdom and Testing Library to verify routing, placeholder behavior, and toast lifecycle.

Vitest thread workers are capped at two after the expanded seven-file suite exceeded this Windows host's worker-startup capacity. Node/fake-indexeddb tests verify Blob persistence and transactional behavior; DOM tests exercise management against isolated real repositories.

## Phase 1B timetable workflow

`src/features/timetable/draft.ts` holds editable source DTOs and pure validation; it never writes or generates lecture records. `src/pages/TimetableImport.tsx` owns the five-step draft and calls only the public data service. `timetable-types.ts` defines its typed review/save contract; internal `timetable-review.ts` resolves stable identities and compares existing values.

Review runs in a read transaction and returns stable pending UUIDs, existing identities, differences and a snapshot. Resolution uses source mappings first, then explicit existing IDs or unambiguous natural matches (term year/semester, course code within term, session course/day/times). Ambiguity, deleted targets and broken mappings block saving. A source key remains stable when its editable code changes. Excluding a draft row does not delete an existing record or mapping.

Save rebuilds the review within one write transaction, checks the snapshot and explicit acknowledgments, then inserts missing academic rows and stores mappings atomically. Existing rows are passed through unchanged and reported skipped. A new revision, concurrent import, invalid reference, quota failure or metadata failure prevents partial writes. Differences offer an explicit keep-existing decision; this workflow does not apply extracted changes to existing academic records. Draft state is memory-only until confirmed save.

The final retained graph is also checked: a kept session's original course must appear in the resulting source mappings, including mappings retained for excluded draft rows. A missing parent blocks review with explicit options to include the saved parent, select a valid saved session, or exclude the session. No session is silently reparented. Before committing, save calls the same source recovery helper inside the write transaction, covering every retained mapping and current relationship. Missing targets, a deleted term or inconsistent relationships roll back all new records and mapping changes. Intact course/session tombstones are validated as retained deletion history and explicitly disclosed, rather than treated as missing data (see F-02 below).

Version 3 adds only `importMappings`, plus optional unindexed term college/program and course activityType fields. No backfill rewrites existing records. The unchanged v2 collision-safe migration has a developer-assisted same-origin recovery runbook in RECOVERY.md. Arabic document language/direction, logical shell positioning and LTR codes/times preserve the dark design tokens. Dashboard/calendar remain placeholders without data integration.

## Phase 1C timetable management

`src/pages/Courses.tsx` replaces only the `/courses` placeholder. The importer remains at `/courses/import` and links to management after save. Management selects a stored term, displays each course with all of its own sessions, and switches to a daily agenda: two columns on desktop, stacked days on small screens. No timetable data, student identity or particular term is built into management logic. Dashboard/calendar remain unconnected placeholders.

`getTimetable(termId?)` performs one consistent read of terms, indexed courses and indexed sessions, without reading attachment Blobs. The default is the latest academic year/semester among active terms; users can select another. Course edits use the existing repository update with captured revision; session edits use `saveManagedSession`. Both patch existing records rather than replacing identity/metadata. Cancel affects only component draft state. Failed writes retain the draft; stale conflicts require explicit cancel/refresh/reconciliation. No automatic cross-tab subscription is added.

`features/timetable/schedule.ts` supplies pure generic time validation/overlap checks, independently of the source extraction. `saveManagedSession` rechecks the exact overlap IDs/revisions within its write transaction before using the existing repository update/insert. It rejects duplicate same-course/day/time slots and parent reassignment. This managed write API does not change importer or low-level bulk/repository contracts.

Deletion previews use existing dependency snapshots. `deleteManagedCourse` permits only a course and its reviewed sessions, rejecting lectures/materials even if a generic cascade would allow them. Session deletion uses default restricted deletion. The UI asks for confirmation only after a safe preview; dependency/revision changes still reject at commit. Import mappings are neither rewritten nor removed, so subsequent imports still resolve edited UUIDs and reject deleted targets. No schema or migration changes are necessary.

New management labels/messages are centralized in `features/timetable/messages.ts`. There was no localization framework to extend. Complete English support needs a parallel catalog, migration of existing shell/import/dashboard/placeholder strings, localized date formatting and accessible labels, locale selection/persistence, document direction updates and bidirectional tests. This phase exposes no language toggle. Existing Arabic RTL, design tokens and LTR identifiers/times remain intact.

Phase 2 supersedes the earlier language/dashboard/calendar deferrals. Out of scope remain monthly calendar, activity tracking, term editing, lecture/material workspaces, PWA, authentication/cloud synchronization, backup/restore and AI.

Service worker caching, installable PWA manifest, cloud sync, authentication, integrations, term/lecture/material editing, complete language switching and backup/restore need later-phase implementation. Production hosts must provide history fallback to `index.html`. The shell is not evidence of offline access or storage support.

## Phase 2.5 lecture workspace

It returns saved/skipped/failed for every file with validation or storage reason codes. Existing IDs never replace bytes, deleted identities are rejected, and parent checks prevent orphans. Partial successes intentionally commit independently. The UI filters successful rows out of retry, retains failed rows/IDs, and uses an immediate ref lock as well as disabled controls to block repeated submissions.

Lecture/file deletion uses default restricted repository deletes with expected revisions and separate visible confirmation. No cascade is requested. Binary download URLs are retained for 60 seconds after initiation and revoked then or on workspace unmount. Filenames are text-rendered; there is no iframe, object, HTML injection, or executable file preview. No schema migration or dependency is needed. Earlier lecture-workspace deferrals are superseded only for this narrow early-beta scope.

### Phase A corrective pass

Public `listImportSources` and `reopenImportSource` use consistent read transactions over existing v3 mappings and the three timetable stores. Reopening reconstructs current values, original source keys, UUIDs and uncertainty metadata, not the original source document. The source chooser never assumes an existing source is new; the selected source is carried in `?source=`. Missing targets, deleted terms, inconsistent parents and ambiguous/damaged mappings fail closed. Existing values and Blobs are never rewritten by these reads.

Unknown course/session identities alongside parent history require explicit selection of a saved UUID or `identity: "new"` on the draft. A newly minted UUID alone is not proof of a new row. An explicit new decision rejects existing mappings, saved UUIDs and exact natural duplicates (including tombstones), rather than silently reusing them. Otherwise mappings, explicit UUIDs and unambiguous exact matches resolve existing identities; mismatched binding/UUID requests fail. Identity decisions are review-only DTO fields, stripped before repository validation/storage. No fuzzy matching or metadata backfill occurs.

Courses captures the opening editor term independently of the current query and rejects same-route retargeting. Its URL is canonicalized after reads/selections, failed transitions hide stale records, and pending transitions lock writes. The production entry uses React Router's data router so `useBlocker` can protect Back/Forward as well as links; explicit keep/discard choices preserve dirty state. During a write, discard is disabled and a localized status explains why. Successful completion refreshes the original term before closing the editor, resets the blocked attempt, and stays on that page; users may navigate again afterward. Per-write tokens invalidate UI completion on unmount/store replacement without pretending to cancel the database transaction. Before-unload warns about unsaved work. Declarative router embeddings retain click/query guards.

Manual setup uses `features/manualSetup.ts`, a shared single-flight operation per repository object, observed with `useSyncExternalStore`. Its fields and pending/failed/saved state survive route unmount/remount. Repeated submissions cannot start a second transaction; a failed transactional create retains fields for retry. Only the initiating mounted instance may navigate automatically. A remounted page shows the saved term and requires explicit continuation. Consuming a success or explicitly cancelling a nonpending draft resets the operation. Separate intentional operations may have identical term values; no time-based or natural-key suppression is used. This operation is memory-only: reloads, tabs and independently constructed repositories do not share it.

`useTimetable` binds results to a new request identity for each term/read attempt, including rapid Back/Forward transitions. Pending and failed reads expose no previous-term snapshot; failure is explicit and refresh retries the requested term. Refreshing the same actual term changes only the read counter, preserving the URL/history entry; changing terms updates the query once.

Source aliases follow a many-keys-to-one-UUID policy. Reopen groups by entity/UUID and presents the oldest mapping (source-key ordering breaks timestamp ties), unions uncertainty flags and reconnects sessions to that representative course key. Every original mapping remains stored and authoritative for later re-import. Multiple distinct term UUIDs, damaged keys, missing targets, deleted terms and parent mismatches still reject. A single draft cannot represent the same UUID twice or rebind an existing key to another UUID.

### F-02 saved source integrity

Managed removal already tombstones the confirmed course/session graph atomically and retains mappings. Recovery now validates the entire mapped graph, including those tombstones, before deriving the active draft. Every mapped target must exist, all course/session term references and session parent mappings must match, and an active session cannot reference a deleted course. The term must remain active. An invalid deletion timestamp also rejects. Deliberately removed courses/sessions appear in the DTO-only `omittedDeletedRows` notice, displayed throughout review in both languages, and never become editable/import candidates. Their mappings, UUIDs, revisions and tombstones remain untouched. This also reopens previously affected sources without a repair write or migration. Original incoming rows bound to deleted identities still reject; this is not restoration. A source with no active courses can reopen with its removal notice but needs valid new draft rows before confirmation. Deletion defaults and historical lecture/attachment protections are unchanged.

Uncertainty confirmation belongs to a recovered entity UUID within one source. A confirmed save copies each reviewed record's exact `unconfirmed` array to all its aliases in that source, preserving keys, UUIDs and creation metadata. Thus clearing flags survives reopen; newly reviewed uncertainty still surfaces. Other sources keep their independent evidence/flags. Recovery conservatively unions disagreeing legacy aliases until an explicit review/save reconciles them. These metadata writes share the academic transaction and stale-review snapshot checks; no schema change or migration is used.

Courses' imperative refresh has a separate pending state bound to store/router/location identity and a per-request token. Navigation/unmount invalidates the token in layout cleanup; production data-router state is also checked on completion because it can advance before React commits effects. A stale result, rejection or finally handler cannot update data, URL, errors or a newer request's loading state. Returning to the same history entry creates a new request context. Refresh does not rewrite an already selected term query; missing/invalid queries can still be canonicalized after a successful current-context read. Existing editor/write behavior and shared Dashboard/Calendar reads remain unchanged.

## F-01 explicit course recovery

`course-restoration.ts` provides internal validated discovery and preview helpers; the public service exposes `getRemovedCourses(termId)`, `previewCourseRestore(id)` and `restoreCourse(id, expectedRevision, snapshot)`. Discovery is scoped to the selected active term and reads no attachment bytes. Restoration reuses the original course UUID, code, term, createdAt and all other domain fields. Only deletedAt, updatedAt and revision change, using the existing write conventions and unique index. UUID/domain/metadata validation runs without repair or normalization; invalid records, missing/deleted terms, unsafe active/cross-term/corrupt session children and stale previews reject. The preview includes the complete course, parent term and sorted child-session records; the write transaction rebuilds it and checks both snapshot and expected revision before the single course put. The resulting record is validated too. All stores participate in the existing transaction scope, so competing connections serialize and a failed write rolls back.

The restoration contract is deliberately **course only**. Managed deletion tombstones active weekly sessions but skips independently deleted sessions; generic reviewed cascades can also tombstone lectures/materials/files. Version 3 does not persist deletion-operation identity. Timestamp equality cannot distinguish those histories, so no sessions, lectures, materials or files are restored or rewritten. A preview lists every related weekly session as remaining removed and explains this before explicit confirmation. No replacement UUIDs are generated. Corrupt/unsafe relationships require explicit investigation; no session-restore or history-repair UI is added.

`RemovedCourses.tsx` adds a separate recoverable-history panel within Courses, with Arabic/English discovery, previews, warnings, results, pending/error/empty/retry states, heading focus and LTR codes/times. The selected term and existing editors are locked while the panel is open; the existing navigation guard prevents discarding an in-flight restoration. An immediate write ref blocks duplicate submissions; service-level revision/transaction checks remain authoritative across tabs. Lifetime-bound reads and writes ignore results after unmount/store replacement. A transaction may finish after a native page departure; remount reads persisted state without replaying it. Recovery retains its opening term independently of read results; post-save refresh cannot silently fall back to another term if the parent is subsequently removed. Successful restoration refreshes the active course snapshot without navigating, and returns keyboard focus to the recovery heading. New wrapping applies only to the recovery panel. Reserved-code feedback directs users to cancel the failed draft and review recovery.

F-02 and import identity policies are unchanged. Reopening before removal, after removal and after explicit restoration preserves every mapping/alias and UUID. A restored course becomes editable again; its sessions still appear in `omittedDeletedRows`. Original incoming rows bound to deleted sessions continue rejecting; importing is never restoration. No schema, migration, dependency, purge, sync, backup/restore or Phase B work is introduced.

## B1 — university table and local text PDF draft

Courses uses TimetableTable: one semantic table, one focusable course row group per UUID and one row per meeting. The original term-bound editors, hash targets, weekly view, safe deletion and F-01 panel remain. PdfDraftTable shares the column frame; editable draft rows remain separate from persisted records. Registration date belongs to Course, never createdAt; lab is an additional activity value. See B1_DESIGN.md for the pre-implementation data gate.

PdfUpload loads features/timetable/pdf.ts only when a user chooses a PDF. Mozilla PDF.js 6.4.299's compatibility build and matching worker are local Vite assets, not a CDN. The compatibility build supports runtimes without newer typed-array APIs. Reference: https://mozilla.github.io/pdf.js/getting_started/. The optional Node canvas package comes transitively from PDF.js and is not a browser dependency. Document bytes are not uploaded, stored, logged or used as a source identity. File names do not select saved sources. Choose an existing source explicitly before re-import; incoming rows resolve through the original review API. Unknown rows in existing history require explicit identities; time/code edits cannot silently create replacements.

The extractor bounds files (10 MiB), pages (20) and text items (50,000), checks PDF headers, destroys tasks on cancellation and ignores obsolete completions. Form editing/next is disabled while parsing. Only recognized academic columns are extracted; student header text is discarded. Coordinate-based line/column grouping supports Arabic/English headers, logical Arabic strings, mixed values, repeated course rows, wrapped cells, weekday names/abbreviations and multiple meetings. Missing required values stay invalid until corrected. An unknown delivery mode uses a draft-only empty sentinel; domain records still accept only the two validated modes. Unsupported activity text is retained in Course.description for review. Dates require explicit ISO YYYY-MM-DD, without locale guessing. Reversed times are never swapped.

All PDF rows are a memory-only draft; selecting a PDF never writes. Existing validation, keep-existing differences, snapshots, aliases, revisions, tombstone protections and saveTimetable's final source check/transaction remain authoritative. Draft exclusions never remove persisted records. A rejected save returns to editing. No alternate PDF writer, restoration path or schema migration exists.

Limitations: recognized text-table layouts only, every nonempty timetable page needs recognizable headers, no OCR or arbitrary-PDF certification. PDF.js can report missing optional standard-font data while extracting built-in-font synthetic fixtures; text extraction is tested, font rendering is not offered. Split/reversed glyph encodings or unclear fields need manual correction. Raw PDF and unsaved drafts are not recoverable after leaving/reload. The compatibility PDF chunk/worker add on-demand bytes; the main bundle retains its existing size warning.

## Phase B1.6 — PDF date evidence and row boundaries

PDF registration dates are interpreted once across the extracted document, before review. Valid ISO values remain unchanged. A valid non-ISO date with a day greater than 12 establishes DD-MM-YYYY only if no valid month-first evidence contradicts it. Invalid calendar dates never establish a format; Gregorian leap years are checked by a strict ISO round-trip. Ambiguous, contradictory and unsupported values stay editable, non-ISO and explicitly uncertain until the student corrects or intentionally omits the optional date. Generic uncertainty acknowledgment cannot bypass existing academic date validation.

Original text and the extraction decision live in draft-only `dateReviews`, displayed in both languages in the preview, detailed course editor and final review. Manual edits retain that evidence. Excluding a draft course removes its notices; a fresh extraction replaces the previous notices. Review snapshots defensively copy the notices and include them in stale-review checks. Raw date evidence is not persisted in courses, mappings or saved sources; only the reviewed optional ISO date is stored. Existing saved dates are never normalized by this parser, and existing keep-user-edits behavior still applies on re-import. No database version or schema change is involved.

PDF body grouping uses the discovered column bounds as well as baseline tolerance. Vertically distinct text in an occupied column starts a new line, so nearby independent rows cannot concatenate their course codes, credits or meetings. Wrapped text and the established Arabic mixed-font layout remain supported. When adjacent course-anchor tolerance windows overlap and contain offset text, ownership is ambiguous: extraction fails through the existing unsupported-layout/manual-entry path instead of guessing a course parent. Grouping keeps per-column baseline state rather than scanning all previous line items.

The upload flow still uses its existing abort-controller ownership checks, same-file input reset, visible loading/errors, explicit cancellation and unmount cleanup. Successful extraction returns to term details; the editable table appears on the following Courses step. B1.6 does not change that navigation or add speculative retry/timeout logic for an unreproduced first-upload failure. PDF scripts, remote services and OCR remain outside the extraction workflow.

Completed creation navigates only after releasing its pending-write guard. Route-owned workspaces and invalidated read contexts ignore obsolete asynchronous results; read failures hide the old workspace and keep retry bound to the requested lecture.

`LectureMedia` provides opt-in native image/audio/video previews from local Blob URLs, with an extension/MIME allowlist and a matching lecture-parent check. Office/PDF/text documents retain the existing binary-download path. File acceptance, 100 MiB limit, stable upload IDs, per-file transaction/retry behavior, revisions, safe deletion and retained Blob tombstones are unchanged. Browser codecs may reject an otherwise accepted media file; download remains available. Extension/MIME checks are not malware scanning or file-content certification.

## Phase C2 — academic Dashboard (pending review)

`getDashboard(termId?)` adds a read-only snapshot to the service boundary. The existing timetable read and an indexed `lectures.courseId` query share one read transaction. Only active lectures under active courses in the selected term are returned, as ID/date/title/link metadata plus `hasNotes`; note bodies do not reach the Dashboard and neither attachment store is queried. IndexedDB still reads whole lecture records for that selected set to derive the notes indicator. No schema, write path, mapping, revision or tombstone behavior changes.

Real storage errors do not select another term. New requests hide the old snapshot, and obsolete responses cannot replace newer navigation. The Dashboard clock never triggers database reads. Course lookup and lecture ordering are memoized per snapshot; occurrence projection is memoized per local minute, while the existing one-second clock updates the countdown/status display.

Dashboard counts describe stored active courses, valid weekly sessions, today's scheduled occurrences, future occurrences in the displayed window, credits, saved lecture records and records with nonblank notes. Limits: the recurring model has no holiday/cancellation or timezone/UTC-offset fields. Refresh/navigation rereads the snapshot; there is no cross-tab live polling. The Dashboard does not certify corrupt term/course records, provide cloud synchronization, or imply an attachment backup.

The shared data-router navigation guard and native unload warning protect drafts and pending operations. Failed saves retain exact input, original revision and stable upload UUIDs; no autosave occurs. Closing a dirty editor and destructive removal each require explicit confirmation.

`AcademicStore.getMaterialLibrary` reads active terms, term-indexed courses and course-indexed materials, without querying either file store. `getMaterialDetails` validates the full term/course/material chain and queries files only for the selected material; returned metadata omits Blob. IndexedDB still reads those selected records, including their Blobs, before projection; it is not a storage-level metadata index or streaming API. `getMaterialFile` returns only the requested active file after full parent validation. No unrelated lecture files are read.

`saveMaterial(MaterialSave)` validates the active term/course, immutable existing course binding and expected revision inside the existing all-store transaction. Caller-supplied material/file UUIDs remain stable across retries. New file IDs must be absent even from tombstones; duplicate batch IDs, invalid file policy, missing/deleted/cross-term parents and stale edits reject the whole save. Existing files are never overwritten. Zero-file materials are valid. The managed operation reuses domain validation, repository revision checks, insert helpers and the existing Lecture Workspace file policy (100 MiB per file, permitted extension/MIME/name and nonempty bytes). Existing low-level repository contracts remain unchanged.

Material removal reuses the existing dependency preview and exact revision snapshot: confirmation tombstones the material and its active files together. Removing one file checks its own revision and active ancestors in the same transaction. No hard deletion, restoration, cascade-policy redesign or storage reclamation is added. Imported mappings, historical lectures and unrelated academic records are untouched.

All attachments are download-only, wrapped with a binary download MIME and sanitized filename; no untrusted document is embedded or executed. Temporary object URLs expire after 60 seconds and are revoked on editor unmount. Extension/MIME checks are not malware scanning. The UI explicitly states that files are local, not backed up or synced. Device quota, cross-tab conflicts, loss of unconfirmed drafts on forced/native departure and memory costs for a very large selected material remain limitations. Offline editing uses IndexedDB in the loaded application; offline cold-start caching/PWA is not introduced. No schema, dependency, PDF, Dashboard or Lecture Workspace behavior changes.
